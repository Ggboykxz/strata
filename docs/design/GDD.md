The GDD is the **executable specification of player experience**, not prose and not a wishlist (master §3.1).
Code contradicting a SIGNED GDD is a BUG. A GDD contradicting the locked High Concept is a DESIGN DEFECT.
A GDD contradicting the Scope Ledger is a SCOPE VIOLATION requiring a trade. A behaviour change updates its
module in the same PR.

## The 19 mandatory fields

A STUB carries only **1, 2, 3, 17, 18** (D138). DRAFT and SIGNED carry all 19. The maturity chain is
**STUB → DRAFT → SIGNED**: a module must be DRAFT before its prototype starts and SIGNED before its content
ships, and it is re-signed at each gate.

| # | field | STUB |
|---|---|---|
| 1 | ID / version / owner / status | required |
| 2 | Player-facing outcome | required |
| 3 | High Concept link | required |
| 4 | Numbered deterministic rules | DRAFT |
| 5 | Numbers with SOURCE or TUNABLE + range + plan | DRAFT |
| 6 | State machine | DRAFT |
| 7 | Data contract, WIRE schemas, version, migration policy | DRAFT |
| 8 | ≥ 5 edge cases | DRAFT |
| 9 | Failure states, including network failure and desync | DRAFT |
| 10 | Interaction matrix | DRAFT |
| 11 | Feedback per state change | DRAFT |
| 12 | Accessibility | DRAFT |
| 13 | Localization | DRAFT |
| 14 | Telemetry + success metric | DRAFT |
| 15 | GIVEN / WHEN / THEN acceptance tests | DRAFT |
| 16 | Perf budget impact: client, server, bandwidth, storage | DRAFT |
| 17 | Explicit out of scope | required |
| 18 | Open questions with owner + deadline | required |
| 19 | Changelog | DRAFT |

**Anti-vagueness (§3.5).** Without a number and a test, these words are forbidden: fun, deep, balanced,
responsive, immersive, many, fast, smooth, scalable, "MMO-scale".

**Coverage (§3.6).** Every task carries `gdd[]`; every shipped system maps to a SIGNED module. GATE:P2
requires ≥ 80 %, P3+ requires 100 %. Missing refs refuse the task. More than 3 open GDD-debt items block
gates above P3.
