## Purpose

Prepare a Next.js dashboard for Vercel as a **dumb renderer** of the repo's existing generated truth. The Director
asked for Next.js + Vercel readiness but chose **"prepare the PR, do not deploy"**. The existing static dashboard
(`apps/dashboard/build.mjs`, `check.mjs`) and the 19/19 `pnpm verify` baseline remain the single truth source and
stay unchanged. The Next.js app only renders values from `apps/dashboard/dist/data.json`; it never recomputes a
metric, calls a live server, handles auth or holds gameplay state.

## Data contract

Single input: `apps/dashboard/dist/data.json`, generated by `apps/dashboard/build.mjs`. The Next.js view reads this
file only and must not import source files or builders to derive its own values.

| group | fields (all metric values are strings) |
|---|---|
| metadata | `generated_at` (metadata, not a metric), `source_metric`, `sources[]` |
| `workflow` | `owners`, `globs`, `active_locks`, `locks_source`, `thread_dirs`, `disputes`, `open_director[]` |
| `concept` | `hc_version`, `t1_en_words`, `t1_en_limit`, `t1_fr_words`, `t3_gate_signature`, `cis`, `cis_reason` |
| `gdd` | `modules`, `draft`, `stub`, `signed`, `coverage` |
| `scope` | `ledger_entries`, `balanced`, `accepted_sessions`, `budget_P0`, `margin_P0`, `variants`, `months_needed` |
| `netcode` | `tick_p50_ms`, `tick_p95_ms`, `down_kb_s`, `up_kb_s`, `desyncs`, `reconnects`, `aoi_entities`, `tracer` |
| `economy` | `inflation`, `faucets`, `sinks`, `sim_status` |
| `tier` | `current`, `authorized`, `granted_by` |
| `netgate` | `status`, `art_allowed` |
| `ai_audit` | `approved`, `blocked`, `rejected` |
| `blueprint` | `tasks`, `gates` |

Rules: render every value verbatim and escaped; a value of `NOT COMPUTABLE` means unmeasured and must stay
`NOT COMPUTABLE` — never recompute, never substitute a plausible number. Ordering and labels come from the file, not
from a second hardcoded table in the view.

## Risks

- **I4 — licence/transitive dependency.** Direct + transitive audit is in
  `docs/legal/DEPENDENCY_AUDIT_NEXTJS.md`. Next 16.4.6 was rejected (LGPL-3.0-or-later via optional
  `sharp`/libvips); the approved pins are Next 14.2.35 / React 18.3.1 with zero forbidden licences in the
  installed closure (`audit-dashboard-deps.mjs` EXIT 0). The rejected finding is retained, not erased.
- **I5 — verification honesty.** Every acceptance command must exist, be run and be logged with a real exit code.
  No fake verification, no skipped gate, no weakened assertion, no self-merge — the Director merges.
- **I7 — secrets/token rotation.** Tokens come from the environment only and are never printed, committed or placed
  in a command that lands in a log. ND-004 (GitHub PAT) and ND-005 (HF token) rotation must precede any Vercel or
  GitHub integration, with a fresh token; neither rotation is an agent action.
- **Stale view.** `data.json` is baked at build time. If `build.mjs` is not rerun after repo state changes, the view
  shows stale values. Mitigation: the root `dashboard:next:build` script chains the dashboard rebuild before the
  Next.js build, and Vercel's buildCommand runs the same chain on each push. No runtime fetch is added as a
  "fix" — that would break the single-truth-source rule.
- **Vercel/rotation coupling.** `vercel.json` and the build script are prepared only. Connecting Vercel, setting
  secrets and deploying are Director-owned steps blocked on ND-004/ND-005 rotation; no deployment occurs in this PR.
- **Scope creep (I8/I9).** One task per PR, no art, no model, no gameplay change; no GDD behaviour change is implied.
